## 고객지원

개별 접수 내용·환자명·접수 시각·병의원·상태 필터는 통합 목록에서 제거했습니다. 각 메뉴는 목록에서 한 행만 사용합니다.

| 메뉴 | 처리 필요 건수 예시 |
| --- | ---: |
| 전화상담예약 | 12 |
| 네이버 예약관리 | 8 |
| 야간통화내역 | 4 |
| 시청자상담 IN | 3 |
| 시청자상담 OUT | 2 |
| 골프 제휴사 고객관리 | 2 |
| 불만해피존 관리 | 4 |
| 고객의 소리 | 3 |
| 칭찬하기 관리 | 2 |
| 상담/비호의적 글 관리 | 2 |
| 합계 | 42 |

“전체 미처리”는 오늘 접수한 건에 한정하지 않고, 접근 가능한 메뉴에서 아직 처리해야 할 업무를 의미합니다. 각 메뉴의 처리 상태를 같은 코드로 가정하지 않습니다. 구현 시 메뉴별 상태 조건으로 집계하며 등록일과 수정일을 혼용하지 않아야 합니다.

하단 예약 통계는 예약만 대상으로 하는 별도 범위입니다. 도넛 예시 합계 96건은 전체 미처리 42건과 다른 지표입니다.

## 간호·원무

병의원 선택 UI를 제거하고 `소속 병의원 · 강남`을 읽기 전용 정보로 표시합니다. 강남은 예시입니다. 실제 로그인 사용자의 `MemberDTO.branchCode`에 해당하는 병의원 데이터만 목록과 집계에 함께 적용해야 합니다.

화면에서 선택기를 숨기는 것 외에 서버의 카운트 API와 바로가기 대상 목록 모두 동일하게 소속 병의원 범위를 제한해야 합니다. 클라이언트가 전달하는 임의의 병의원 코드로 조회 범위를 넓히면 안 됩니다.

간호의 6개 카드와 합계 42건, 원무의 3개 카드와 합계 19건은 기존 시안과 같습니다. 연말정산은 한방 미처리 3건 + 양방 미처리 2건 - 양쪽 모두 미처리 1건 = 고유 접수 4건입니다.

## 원외탕전실

| 기존 메뉴 | 처리 필요 건수 예시 | 원본 화면 |
| --- | ---: | --- |
| 한약 원내비치요청서 | 12 | `src/main/resources/templates/herb/request/herb/list.html` |
| 약침 원내비치요청서 | 7 | `src/main/resources/templates/herb/request/pharm/list.html` |
| 반송약관리 | 5 | `src/main/resources/templates/herb/request/returnRequest/list.html` |

한약·반송약 화면은 행정팀·조제팀·환제팀·탕전팀·배송팀의 확인 필드 `team1..team5`가 있습니다. 약침 화면은 행정팀·조제관리팀의 `team1..team2`가 있습니다. 서로 다른 확인 필드 구성을 참고해 각 메뉴에서 관련 팀 확인이 남은 요청을 집계하는 시안입니다.

동일 요청에 여러 팀의 확인이 남아 있어도 해당 메뉴의 요청 UUID 기준 1건으로 집계합니다. 구체적으로 어떤 팀 확인을 해당 담당자의 처리 대상으로 볼지와 Bool 필드의 미확인·NULL 규칙은 실제 업무 정책에 맞춰 정해야 합니다. “확인 대기”는 설명 문구이며 새 DB 상태 코드를 가정한 것이 아닙니다.

`HerbQueryRepository`와 `ReturnReqQueryRepository`에는 `orgCode`에 따라 소속 탕전실의 병의원 범위를 제한하는 조건이 있습니다. `PharmQueryRepository`에서 확인한 조회는 날짜 조건만 있으므로 대시보드 구현 때 약침에도 해당 권한의 범위를 적용해야 합니다. 간호·원무의 “단일 소속 병의원”과 원외탕전실의 “담당 탕전실에 연결된 병의원 범위”는 구분합니다.

## 미디어팀(담당)

기존 `활동내역 관리` 메뉴의 `checkState = '확인요청'` 게시글을 예시 18건으로 표시합니다. 카운트와 바로가기는 동일한 상태 조건을 사용합니다.

근거:

- `src/main/java/com/jaseng/aio/mediateam/activity/ActivityController.java`: 메뉴명 활동내역 관리.
- `src/main/java/com/jaseng/aio/mediateam/activity/entity/ActivityEntity.java`: `checkState`, `uuid`, 삭제 여부.
- `src/main/java/com/jaseng/aio/mediateam/activity/ActivityQueryRepository.java`: 상태·병의원·유형별 조회.
- `src/main/resources/templates/mediateam/activity/list.html`: 확인요청·수정필요·수정완료·등록완료 상태.

파일 첨부 조인으로 게시글이 중복 집계되지 않도록 UUID 기준으로 셉니다. 기존 삭제 제외 규칙과 메뉴 접근 범위도 적용해야 합니다.

`ActivityEntity`에서 검토 담당자별 소유 필드는 확인하지 못했으므로 “내 이름으로 배정된 게시글”이라는 새 조건은 가정하지 않았습니다. 이 시안은 미디어팀 담당 권한으로 접근 가능한 확인요청 글 기준입니다. 수정완료 글의 재검토도 포함해야 하는지는 업무 정책에 따라 별도 결정하며 이번 카운트에는 포함하지 않았습니다.
